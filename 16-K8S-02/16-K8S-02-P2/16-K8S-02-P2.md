## Single-node Kafka



### Namespace

```bash
kubectl create namespace kafka-yaml
```



### The manifests

We have two files on directory `manifests` as follows:

`01-kafka-service.yaml`

> 🔴 **Why two services in one config file**?
>
> **1. `kafka-headless`** :  gives the pod a **name**: `kafka-0.kafka-headless...` Used by Kafka itself (controller voting, broker ID).
>
> **2. `kafka-bootstrap`** :  gives clients a **door**: `kafka-bootstrap:9092` Used by your `kafka-console-producer.sh` commands.



`02-kafka-statefulset.yaml`

> 🔴 **Deployment vs StatefulSet**
>
> - **Deployment**: interchangeable pods, no identity, shared nothing. Good for stateless apps (web servers, APIs).
> - **StatefulSet**: each pod is unique and remembers who it is. Good for databases, Kafka, ZooKeeper, Elasticsearch.



### Generate the cluster ID

```bash
kafka-storage.sh random-uuid
```

Copy the printed UUID into `02-kafka-statefulset.yaml`, replacing `REPLACE_WITH_GENERATED_UUID`.



### Apply and verify

```bash
kubectl apply -f 01-kafka-service.yaml

kubectl apply -f 02-kafka-statefulset.yaml

kubectl -n kafka-yaml get pods -w
```



## See this cluster on OffsetExplorer

```powershell
kubectl -n kafka-yaml port-forward pod/kafka-0 30092:30092

# Add localhost:30092 to offsetexplorer

# Your PC localhost:30092 <---> K8S API server <---> Pod kafka-0:30092
```



### Test it

```powershell
kubectl -n kafka-yaml exec -it kafka-0 -- /opt/kafka/bin/kafka-topics.sh `
  --create --topic demo-topic --partitions 1 --replication-factor 1 `
  --bootstrap-server kafka-bootstrap:9092

kubectl -n kafka-yaml exec -it kafka-0 -- /opt/kafka/bin/kafka-console-producer.sh `
  --topic demo-topic --bootstrap-server kafka-bootstrap:9092

kubectl -n kafka-yaml exec -it kafka-0 -- /opt/kafka/bin/kafka-console-consumer.sh `
  --topic demo-topic --from-beginning --bootstrap-server kafka-bootstrap:9092
```

