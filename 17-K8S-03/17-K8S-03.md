## What Falco does in a nutshell 

Falco watches **system calls** (the low-level interface between applications and the Linux kernel) and matches them against a set of **rules**. When behavior looks abnormal, it fires an alert.



## Install [Falco](https://github.com/falcosecurity/falco)



### Step 1: Add the Helm repository

```bash
helm repo add falcosecurity https://falcosecurity.github.io/charts

helm repo update
```



### Step 2: Install Falco

The command below uses the **modern eBPF driver** and disables the falcoctl artifact downloader, which is often blocked by firewalls.

```bash
helm install falco falcosecurity/falco `
  --namespace falco `
  --create-namespace `
  --set driver.kind=modern_ebpf `
  --set falcoctl.artifact.install.enabled=false `
  --set falcoctl.artifact.follow.enabled=false `
  --set tty=true
```

**Why these flags matter:**

| Flag                                      | Purpose                                                      |
| :---------------------------------------- | :----------------------------------------------------------- |
| `driver.kind=modern_ebpf`                 | Uses the modern eBPF probe bundled in the Falco binary. No kernel module compilation needed. |
| `falcoctl.artifact.install.enabled=false` | Skips the init container that downloads rules from the internet. **Avoid 403 error**. |
| `falcoctl.artifact.follow.enabled=false`  | Skips the sidecar that continuously fetches rule updates. **Avoid 403 error**. |
| `tty=true`                                | Enables proper terminal event capture for the task.          |

> 🔴**Note:** Disabling `falcoctl` means you will **not** receive automatic rule updates. That is fine for a demo but **not recommended for production**.

## Write a Custom Rule

### Step 1: Create the rule file

Create `falco-rules.yaml` on your local machine:

```yaml
customRules:
  custom-rules.yaml: |-
    - rule: Write below /etc in container
      desc: Detect any write to /etc inside a container
      condition: >
        (evt.type in (open,openat,openat2) and evt.is_open_write=true and fd.typechar='f' and fd.num>=0)
        and fd.name startswith /etc
        and container
      output: >
        File below /etc opened for writing
        (file=%fd.name process=%proc.name container=%container.name pod=%k8s.pod.name)
      priority: WARNING
      tags: [filesystem, mitre_persistence]
      
```

> The above config, watches every container on your nodes at the syscall level and fires a `WARNING`-priority alert **any time a process opens a file under `/etc` for writing**.
>
> See a complete tutorial at this URL: https://falco.org/docs/reference/rules/



### Step 2: Apply the rule

```bash
helm upgrade falco falcosecurity/falco `
  --namespace falco `
  --reuse-values `
  -f falco-rules.yaml
```

```bash
kubectl get pods -n falco -w
```

### Install [falcosidekick](https://github.com/falcosecurity/falcosidekick)

A simple daemon for connecting [`Falco`](https://github.com/falcosecurity/falco) to your ecosystem. It takes a `Falco` events and forward them to different outputs in a fan-out way.

First add the `falcosidekick`  to Falco as follows:

```powershell
helm upgrade falco falcosecurity/falco `
  -n falco `
  --reuse-values `
  --set falcosidekick.enabled=true `
  --set falcosidekick.config.talon.address=http://falco-talon:2803 
```

> We see two instances of `falcosidekick`. If you want to know why, run this command:
>
> ```
> helm get values falco -n falco --all
> ```
>
> If you wanted to reduce the number of replicas, run this command:
>
> ```
> helm upgrade falco falcosecurity/falco `
>   -n falco `
>   --reuse-values `
>   --set falcosidekick.replicaCount=1
> ```



### Install [Talon](https://github.com/falcosecurity/falco-talon) 

`Falco Talon` is a Response Engine for managing threats in your Kubernetes.

Install falco-talon with one replica: 

```powershell
helm install falco-talon falcosecurity/falco-talon `
  --namespace falco `
  --create-namespace `
  --set replicaCount=1
```

```powershell
kubectl get pods -n falco
```



### Create custom rules

Create a file named `talon-values.yaml` with the following content. This file will impose some rules for Talon.

```yaml
# talon-values.yaml
config:
  watchRules: true

  rulesOverride: |
    - action: Terminate Pod
      actionner: kubernetes:terminate
      parameters:
        ignore_daemonsets: true
        ignore_statefulsets: true
        grace_period_seconds: 5

    - rule: Terminal shell in container
      match:
        rules:
          - Terminal shell in container
        output_fields:
          - k8s.ns.name!=kube-system, k8s.ns.name!=falco
      actions:
        - action: Terminate Pod
```

> 1- Automatically kill any pod where someone opens an interactive shell, except in the system and Falco namespaces, within 5 seconds, unless it's a DaemonSet or StatefulSet. Indeed, any pod owned by a DaemonSet or StatefulSet, in **any** namespace, is skipped by the terminate action.
>
> 2- `grace_period_seconds: 5` It tells Kubernetes to give the pod's process **5 seconds to shut down gracefully** (via `SIGTERM`) before force-killing it (`SIGKILL`). **SIGTERM**  comes from **SIG**nal + **TERM**inate.
>
> 3- Note that part `k8s.ns.name!=kube-system, k8s.ns.name!=falco` says, **only** react if the event's namespace is **not** `kube-system` and **not** `falco`. In other words, don't kill pods just because someone opened a debug shell into a system component or into Falco/Talon's own pods.
>
> 4- See a complete tutorial at this URL: https://falco-talon.github.io/docs/rules/.



Now, upgrade Talon to take the above effects:

```powershell
# cd to the directory that file `talon-values.yaml` is there:

helm upgrade falco-talon falcosecurity/falco-talon `
  -n falco `
  -f .\talon-values.yaml `
  --set replicaCount=1
```

Check if the pods are all OK:

```powershell
kubectl get pods -n falco -w
```
