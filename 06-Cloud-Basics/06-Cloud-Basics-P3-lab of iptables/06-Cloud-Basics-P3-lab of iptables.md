## Block One Specific IP by `iptables`

```bash
# Allow port 5001 ONLY from MY-PUBLIC-IP
sudo iptables -A INPUT -p tcp --dport 5001 -s 🔴MY-PUBLIC-IP🔴 -j ACCEPT

# Block port 5001 from all other IPs
sudo iptables -A INPUT -p tcp --dport 5001 -j DROP

===========================================================

# DROP my IP for one particular port
sudo iptables -A INPUT -p tcp --dport 5001 -s 🔴MY-PUBLIC-IP🔴 -j DROP
```



> **Explanation of `iptables` options:**
>
> `-A INPUT` ===> append rule
>  `-p tcp` ===> TCP traffic
>  `--dport 5001` ===> destination port 5001
>  `-s MY-PUBLIC-IP` ===> source IP
>  `-j DROP` ===> **drop matching packets** 🚫



## One more advanced scenario

- Suppose you have two servers, A and B. generate a key on server B as follows:


```bash
ssh-keygen -t rsa -b 4096

# ✅ -t rsa = "Type". This tells SSH to use the RSA encryption algorithm. Think of it as #choosing the type of lock and key you want to make. RSA is the classic, universally #compatible standard.

# ✅ -b 4096 = "Bits". This tells SSH to make the key 4,096 bits long. Think of this as the # complexity of the lock.
```

- Then put the public key (`id_rsa.pub`) on the file `authorized_keys` of server A (This address `/home/your_username/.ssh/authorized_keys`). Now easily SSH from server B into server A and enjoy.


- In production envs, the backup server should **pull** its desired data from main server. If main server push backups to backup server and if someone get access to main server, all our backup data will be gone. **SO PAY MUCH ATTENTION TO THIS MATTER**.
  - **Pull:** Backup server holds the private key ===> it can SSH **into the main server** and pull data.
  - **Push:** Main server holds the private key ===> it can SSH **into the backup server** and push data.
- With `iptables` we can set rules on main server that only the backup server can ssh into it (and pull its data). This is a strong condition for safety of our backups.

## Close port 22 for all except you

```bash
# Set default policy to DROP (blocks everything)
# Note that this is a policy and not a rule.
sudo iptables -P INPUT DROP

# Allow established connections- Rule #1
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow localhost- Rule #2
sudo iptables -A INPUT -i lo -j ACCEPT

# Allow SSH ONLY from your IP (replace with your actual IP)- Rule #3
sudo iptables -A INPUT -p tcp --dport 22 -s 🔴YOUR_ACTUAL_IP🔴 -j ACCEPT

# Save rules
sudo netfilter-persistent save

```

> 1- Packets arrive at our server, and `iptables` checks them against the rules **in order**. If a packet doesn't match any of the rules, the default policy (`DROP`) takes effect.
>
> Note that, **the first matching rule determines the action**.
>
> 2- Since your default policy is:
>
> ```bash
> -P INPUT DROP
> ```
>
> without the `lo` rule, **loopback traffic arriving through `INPUT` would be dropped**.
>
> 3- This rule allows packets belonging to **already-established connections**, including your SSH session:
>
> ```bash
> -m state --state ESTABLISHED,RELATED -j ACCEPT
> ```
